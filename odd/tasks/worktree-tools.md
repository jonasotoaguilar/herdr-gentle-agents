# Worktree tools for agents
Expose worktree create/list/close as extension tools so the manual rule in `~/.pi/agent/AGENTS.md` becomes callable, with issue association, odd capture and creation hooks.
Branch: `feat/worktree-tools`. Worktree: `.../herdr-gentle-agents-worktrees/feat-worktree-tools` (flattened slug). Base: `origin/main` 806e332 — the merged two-package split; this branch was rebased onto it, and the only integration change was relaxing `tools/package-identity.test.js` from a closed single-extension list to membership, because the Pi package legitimately declares a second extension now.
Delivery: feature-branch-chain, built with **gh-stack**, tracker plus six slices of one work unit each. Runner: `node --test tools/*.test.js`. Actual size: about 5,000 authored lines, so four slices exceed the repository's 800-line review budget on their own and carry `size:exception` with their rationale; tests ship with the unit they verify, which is what makes those slices large.

S12. Surface decision (parent, from primary Pi docs): extension tools via `pi.registerTool()`. Codemode is a QuickJS sandbox with no filesystem, network or timers and adds no tools, so it cannot implement this; it may call these tools.
S13. Close must drop every registry row that refers to the checkout it removed, including a row whose path reaches it through a symlink: the removal is by resolved identity, so the bookkeeping must match by resolved identity too (compare realpaths, never the process cwd). Basis: the user authorized the hardening list with "bien aplicas las mejoras".
S14. `worktree_create` must never unregister a live checkout: a registry row that carries the branch being created but points at a DIFFERENT live checkout is not replaced or removed; the live checkout keeps its registration. Basis: same authorization.
S15. When a removal vanishes a checkout other than the target, the failure names that path even when the remover itself exits non-zero. Detection before the early return, never a bare "removal failed". Basis: same authorization.
S16. `worktree_list`, when it obtains the listing, verifies that every registered path exists; a path that no longer exists (the user deleted it by hand) is removed from the listing AND pruned from the registry, so the tool always exposes only real checkouts. Verbatim: "Otra tambien rs que la tool de list worktree al obtener el lista revise que los path (wortree existen) si alguno ya no esta (usuario borro a mano) lo eliminado del listado. Y asi la tool expone solo los reales siempre." A checked-out path that git still records is named in the warning, because git may hold the worktree record until `git worktree prune`.
S17. `min_herdr_version` states the version this code has actually been exercised against, not a guess: 0.9.3 when every command the plugin depends on is available there, proven by running them, and 0.9.4 only if one is missing. Basis: the user authorized "todas las optimizaciones".
S18. Release, once everything is implemented and merged: per-package tags (`pi-v0.5.0` for the npm-published Pi package, `herdr-v0.4.0` for the git-installed Herdr plugin), each with its GitHub Release, and the npm publication attempted. A blocked npm credential is reported honestly, never faked. Verbatim: "una vez todo es implementado saca la release".
S19. The listing shows the principal checkout, distinguished, and the session's own checkout first. Verbatim: "para la lista de wortrees debe aparecer igual el repo principal distinguido. Y el primero que aparece en la tool debe ser el del path de la sesion, si esta en el rpincipal o en u. worktree". Decisions fixed here so the format is never guessed: the principal is the MAIN worktree of the repository, recovered from the shared git common dir and never from the caller's toplevel (which is itself a worktree when the session runs inside one) and is printed as `worktree list: <path> <branch> principal`, never with `thread=`/`issues=`, and is never pruned because the registry holds agent rows only; the session's checkout is the checkout that contains or equals the tool context's cwd (deepest match wins, the principal is a candidate) and it is the FIRST line, followed by the principal and then the remaining agent rows in registry order; when there are no agent worktrees the output is exactly the principal line, so `worktree list: none` no longer exists — the contract evolution this request implies; `details.worktrees` entries carry `kind` of `principal`, `agent` or `unregistered`; and when the principal cannot be determined from git's listing, no principal line is invented.

S20. An existing branch is adopted, never created. Verbatim: "tambien si al crear worktree con tool si la rama existe por lógica no la crea, el worktree simplemente se adueña de ella". Decisions fixed here: before creating, the tool resolves whether `refs/heads/<branch>` exists; when it does (and the branch is not checked out at a live checkout, already refused), the worktree checks out that EXISTING branch — no `-b`, the branch ref is never created, rewritten or deleted — and the result reports it (`details.branchCreated: false` plus a warning naming the adopted branch); when it does not, creation keeps today's behaviour (herdr first, git `worktree add -b` with base HEAD) and reports `branchCreated: true`. Because herdr's `worktree create` cannot adopt an existing branch, the adopt case goes through git and then associates the Herdr workspace best-effort with `herdr worktree open --path <path> --cwd <root>`, reporting whether that association happened; the checkout succeeding never depends on herdr.
S21. Creation creates no symlinks. Verbatim: "tambien mejor saca lo que hacw symlink a odee, .agents y los demas.quita esa feactue/hook de la creacion, esta demas y puede traer conflictos". This supersedes S8's symlink requirement: the creation hooks no longer create any symlink (`odd/`, `.agents/`, `.claude/` or any other) and no longer create `odd/` in the principal, because that directory existed only to be linked. The remaining hook steps are unchanged: untracked env copies, stack-detected dependency installs, and `codegraph init` when available. Consequences recorded rather than hidden: the odd capture (S5) stays, and a worktree reaches `odd/` only when the repository tracks it — a tracked `odd/` is a real directory there too, so the capture records both the worktree-relative document and the principal's absolute path, while an untracked `odd/` is reachable in the principal alone; and closing a tool-created checkout still needs `force` wherever env copies leave untracked files.
S22. Existence is an error on both sides. Verbatim: "al usar lista de worktrees si algun path ya no existe lo saca del listado/registro. Si al crear un worktree ya existia lanzar error y avisa. Si al intentar eliminar un worktree que no existe ya igual avisa con error". Two of the three statements already hold and are NOT re-implemented: the listing prunes a path that no longer exists (S16), and closing a path that is not registered fails with `no registered worktree for "<key>"` plus the closest names. The new rule is the strict reading of the middle statement: ANY pre-existing entry at the target path — a non-empty or EMPTY directory, a file, a FIFO, a symlink, a dangling symlink — is refused with an actionable message naming what is there and what to do, before any backend runs, and never git's raw `fatal: ... already exists`; an empty directory is included precisely because git would silently adopt it. The one exception is the thread's own registered checkout, which the idempotency contract (L10) returns as `created: false`.

S23. The session moves to another checkout by NAME. Verbatim: "para lo del wap se necesita solo el nombre del qorktree no la ruta completa. Igual el lista quizas sea mejor sacar el path o mostrarlo solo con el nombre para que coincida con el warp la info". The surface is decided by the platform, not by preference: `waitForIdle`, `switchSession`, `newSession`, `fork`, `navigateTree` and `reload` live on `ExtensionCommandContext` (`dist/core/extensions/types.d.ts:280-320`), documented as "session control methods only safe in user-initiated commands", so a tool context does not have them and the warp is the COMMAND VERB `/herdr-gentle:worktree warp <name>` — never a `worktree_warp` tool, which the platform makes impossible. The name is the flattened branch slug (`feat/worktree-warp` -> `feat-worktree-warp`), exactly the identifier S24 prints, and the principal is named `principal`. An unknown or ambiguous name fails closed and names the known ones; warping to the checkout the session already runs in reports that and changes nothing. Mechanism, read from the upstream reference and checked against the installed types: `await ctx.waitForIdle()`; capture `{file: getSessionFile(), leaf: getLeafId(), cwd: ctx.cwd, sessionDir}` and refuse when there is no persisted session; `SessionManager.forkFrom(file, targetCwd, sessionDir)` — or, for a session Pi has not written to disk yet (a brand-new session lives only in memory), clone the in-memory entries into a session allocated for the target cwd via `SessionManager.create` + `open`; `branch(leaf)` (or `resetLeaf()` when there is no leaf) plus one `appendCustomEntry` transition record naming both cwds; then `ctx.switchSession(targetFile, { withSession: r => r.ui.setStatus(...) + r.sendMessage(..., {triggerTurn: false}) })`, whose message tells the session to revalidate every path and cwd-dependent assumption. `cancelled` is a real outcome, not a success: it removes the target session file and changes nothing else. Measured scope of the move, so nothing is over-promised: the SESSION cwd changes and the tools operate in the target, while the PROCESS cwd does not (Pi never calls `process.chdir`); emitting OSC-7 (`ESC ] 7 ; file://<cwd> ESC \`, only when stdout is a TTY) tells the TERMINAL the new cwd, and Herdr honours it natively because it embeds ghostty-vt, which parses OSC 7 into its pane pwd, so new panes, tabs and workspaces with `new_cwd = "follow"` inherit it — no cmux-style socket protocol is needed; the interactive bash shell in that pane does NOT change directory, because a child process cannot change its parent shell's cwd. The OSC-7 leg is verified against `herdr pane`'s `foreground_cwd` before it is claimed to work, never assumed.

S24. The listing identifies checkouts by NAME, and the other commands accept that name. Verbatim: "Igual el lista quizas sea mejor sacar el path o mostrarlo solo con el nombre para que coincida con el warp la info". Decisions fixed here: the first column of every `worktree list:` line becomes the NAME — the flattened branch slug, or `principal` for the principal checkout — so the printed identifier is exactly what `warp` accepts and what `close` can take; the absolute path is not lost, it moves to `details.worktrees[].path`, which already carries it; `worktree_close` gains `name` as a third selector beside `path` and `branch` (at most one of the three), resolving the same slug rule, and an unknown name fails closed like an unknown path, naming the closest names. This is a deliberate evolution of the S6/S19 output text, so the pinned tests and `docs/worktree-tools.md` move with it in the same commit.

## Design

Decisions locked before implementation (recorded in Engram observation 9006, restated here so this document is self-sufficient):

D1. Surface: Pi extension tools registered with `pi.registerTool()` in a new file `extensions/gentle-worktree-tools.ts`, listed in the Pi package's `pi.extensions`. Never codemode.
D2. Three tools: `worktree_create(branch, issues[])`, `worktree_list()`, `worktree_close(path|branch, force?)`. Create and close prompt for approval; list is read-only. Failures return `isError: true` with structured content. Success output is terse: `worktree create: <path>`.
D3. Path: flatten the branch into the slug (`feat/foo-bar` -> `feat-foo-bar`) at `<repo-parent>/<repo-name>-worktrees/<slug>`, matching the rule in `~/.pi/agent/AGENTS.md`.
D4. Registry: `<git-common-dir>/pi-worktrees.json` — inside `.git`, never in a working tree, never committed, shared by every worktree of the repository. Entry `{branch, path, thread, issues[], odd[], createdAt, updatedAt}`.
D5. Issues: at least one issue NUMBER is mandatory; each is verified to exist through `gh`; no `status:approved` requirement. Empty or missing issues is an error telling the agent to create or assign an issue first. When `gh` is unavailable or there is no GitHub remote the tool fails closed with a clear message.
D6. Close removes the worktree and its Herdr workspace, keeps the branch, drops the registry entry; a dirty checkout requires `force`.
D7. odd capture: intercept the Pi tool pipeline (`pi.on` tool_call/tool_result) and extract paths for read/edit/write, associating the `.md` to the worktree of the agent's context, never by file identity, because `odd/` is a symlink into the principal checkout. A re-scan of the worktree's `odd/*.md` complements it; bash commands touching `odd/` are not reliably parseable and that limitation is documented.
D8. Creation hooks: copy unversioned files with a real existence check; install dependencies by lockfile-detected stack (bun/pnpm/yarn/npm, `uv sync`, `cargo fetch`, `go mod download`); symlink `odd/` always (creating it in the principal checkout when absent), `.agents/` and `.claude/` only when they exist; never symlink `.codegraph/`; run `codegraph init` when the CLI is available.
D9. Mode: `/herdr-gentle:worktree enabled|disabled|status` following the `/herdr-gentle:sidebar` pattern with a shared mode file in the plugin state directory, default enabled, gating both registration and execution, and reporting whether `/reload` is needed.
D10. Reuse from the `pi-herdr-worktree` reference: closed operation union with per-operation allowlisted argv, values always passed as separate argv (herdr rejects `--flag=value`), `git check-ref-format` for branch validation, rejection of leading dashes and Unicode bidi/newline, absolute normalized path outside every checkout and the gitDir, refusal when the branch is already checked out or the path is a live worktree, verification against `git worktree list --porcelain -z` before and after instead of trusting Herdr JSON, a per-repository mutex, and a deduplicated `before_agent_start` guidance note.
D11. Scope: the `~/.config/herdr` `worktree-hooks` plugin stays untouched in this feature; the double-run hazard is resolved when it is replaced.

### Module interfaces (frozen for every slice)

`lib/worktree-git.js` — argv-safe process and git plumbing:
- `runArgv(bin, args, opts)` -> `{status, stdout, stderr, error}`, never a shell string.
- `repoIdentity(repoRoot)` -> `{root, commonDir, repoName, parentDir}` using `git rev-parse --show-toplevel` and `--git-common-dir`.
- `slugifyBranch(branch)` -> flattened slug, `worktree` when nothing survives.
- `worktreePath(repoRoot, branch)` -> absolute target path.
- `validateBranch(name)` -> `{ok, reason}` via `git check-ref-format --branch`, rejecting empty, leading `-`, whitespace, control characters and Unicode bidi marks.
- `listWorktrees(repoRoot)` -> `[{path, branch, head, detached, bare}]` from `git worktree list --porcelain -z`.
- `isPathInAnyCheckout(repoRoot, target)` and `herdrArgv(operation, params)` (closed union, per-operation allowlist).

`lib/worktree-registry.js` — the registry at `<git-common-dir>/pi-worktrees.json`:
- `registryPath(repoRoot)`, `readRegistry(repoRoot)` -> `{version, worktrees}` where malformed content is reported, never thrown and never silently enabling.
- `findByBranch(repoRoot, branch)`, `findByPath(repoRoot, target)`, `findByThread(repoRoot, thread)`, `upsertWorktree(repoRoot, entry)` (replaces by branch), `appendWorktree(repoRoot, entry)` (always appends, for the S14 create guard), `removeWorktree(repoRoot, key)`, `removeWorktreeByPath(repoRoot, absolutePath)` (drops every row reaching the checkout by resolved identity: same absolute value, realpath equality, or a live-or-dangling symlink referent via an explicit readlink walk that never touches the process cwd; relative rows never match), `pruneWorktrees(repoRoot, absolutePaths)` (drops every absolute-path row in the set in one locked atomic write for the S16 list self-heal; relative rows never match), `removeWorktreeExact(repoRoot, branch, entryPath)`, `addOddDoc(repoRoot, key, relPath)`.
- Writes are atomic (temporary file plus rename) and serialized by `withRegistryLock(repoRoot, fn)` using an exclusive lock file beside the registry with a bounded wait.

`lib/worktree-mode.js` — shared mode file:
- `stateDir(env)` resolved exactly like the sidebar's (`GENTLE_STATUS_STATE_DIR`, else `$XDG_STATE_HOME/herdr/plugins/herdr-gentle-agents`), `modePath(env)`, `readMode(env)` -> `{state: missing|enabled|disabled|malformed, enabled}` with missing meaning enabled and malformed never enabling, `writeMode(enabled, env)`.
