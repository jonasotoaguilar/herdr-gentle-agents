# Two-package split: Pi package + Herdr plugin
Split this repository into two independently installed, independently versioned packages — a Pi package installed with `pi install` and a Herdr plugin installed with `herdr plugin install <OWNER/REPO/herdr-plugin>` — plus one script that installs both, and an update story for each side.
Branch: `feat/packaging-split`. Worktree: `.../herdr-gentle-agents-worktrees/feat-packaging-split` (flattened slug). Base: `origin/main` 6023e86.
Delivery: feature-branch-chain of slices of ~400 authored lines, built with `gh-stack`, merged to `main`. Runner: `node --test tools/*.test.js`.

Distribution decisions, recorded verbatim in `odd/tasks/worktree-tools.md` L8: the Pi side IS published to npm as `@jonasotoaguilar/herdr-gentle-agents` with the `pi-package` keyword, so the Pi install is `pi install npm:@jonasotoaguilar/herdr-gentle-agents` and updates come from `pi update --extensions`; the Herdr plugin keeps installing from git.
S5. Layout, recorded in L9 from the Pi docs (`packages.md`, `cli.md`) and `herdr plugin install --help`: the repository root is the Pi package and `herdr-plugin/` is the Herdr plugin, because Pi expects `package.json` at the package root while Herdr accepts a subdirectory (`herdr plugin install <OWNER/REPO[/SUBDIR]>`, verified again in this session against herdr 0.9.3, which also provides `herdr plugin update`). INSTALLATION PINNING (verified in the Pi docs): versioned npm specs and git tags/commits are pinned and never move on update, so both sides must be installed unpinned to receive updates.
S6. Autonomy, verbatim: "implementa todo el plan en auto, no hagas preguntas y toma tus propias deciciones. No te detengas hasta tener todo mergeado. Usa cadena feature, 400, commits atomicos. S7. Behaviour preservation: the released v0.4.0 behaviour must survive the move unchanged — daemon and polling with lifecycle-event refresh, the `configure`/`unconfigure`/`doctor`/`whois` actions, `/herdr-gentle:sidebar` toggle semantics with the owned native exclusion and managed row, `min_herdr_version = 0.9.4`, and the read-only diagnostics contract. Existing tests that pin behaviour sharing the code being moved stay green; only tests that pin the retired managed-copy install contract are rewritten.
S8. Ownership rule that shapes the split: the Pi package must be installable and usable on its own, so it owns the Pi-side helpers (extension, exclusion helper, sidebar bridge, mode file, Pi settings writes); the Herdr plugin owns the runtime Herdr consumes (manifest, daemon, configure, diagnostics, token contract). Cross-package calls go through the installed Herdr plugin root, never through a repo-relative path.
