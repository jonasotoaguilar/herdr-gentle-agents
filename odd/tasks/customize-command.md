# Customize command: one panel for the three toggles
Replace `/herdr-gentle:sidebar`, `/herdr-gentle:moshi` and `/herdr-gentle:worktree` with a single `/herdr-gentle:customize` panel that shows all three switches with a one-line description each, applies the chosen change immediately, and reloads the extension runtime only when the change cannot take effect without it. A separate `/herdr-gentle:warp` command offers the project's checkouts as a selector and moves the session to the chosen one.
Branch: `feat/customize-command`. Worktree: `.../herdr-gentle-agents-worktrees/feat-customize-command` (flattened slug). Base: `main` f54595d.
Delivery: three work-unit commits on one branch (warp command, panel, removals), single PR at the end. Runner: `node --test tools/*.test.js` (what CI runs). Slice sizes are recorded as they land and the PR carries the repository's `size:exception` label when a slice exceeds its 800-line review budget, exactly as the previous feature did: the warp commit is 1596 changed lines (1177+/419−), and almost all of it is the MOVE of the 937-line warp suite out of `tools/worktree-mode-command.test.js` (423 deletions there), not new logic — 184 authored source lines plus 12 new tests are the real surface, and splitting a move from the tests that keep covering it would only hide that. Tests ship with the unit they verify; that is the recorded rationale for this exception, not a licence to grow slices.

S2. Panel shape, answered by the user: "Panel de 2 paneles (como gentle-shell)". Two panes in one overlay — left column `CATEGORIES` with the three switches, right column their two rows each marked with `→` on the active value, one detail line per row saying what it turns on or off, a preview line, and a footer with the key hints; `Esc` closes without writing. Rendered through `ctx.ui.custom(factory, {overlay:true, overlayOptions:{anchor:"center", width:"70%", minWidth:60, maxHeight:"85%"}})` — the same host surface gentle-shell uses at `extensions/gentle-shell.ts:2453`; its view is internal to that package so ours is written here, not imported.
   Copy is fixed here so the panel never invents it (English, matching the file's existing messages): title `Customize · Gentle Herdr`; left heading `CATEGORIES` with categories `Agentes sidebar`, `Moshi notifications`, `Worktree tools`; the right pane is headed by the category name; rows carry a `→` on the active value and one detail line each — sidebar `Gentle (this extension)` / `publishes agent state and SessionChanges from Gentle` versus `Native Herdr` / `hands the pane back to Herdr's own agent state`; moshi `On` / `notifies ask and finish episodes through Moshi` versus `Off` / `leaves notifications to the host`; worktree `Enabled` / `agents can create, list, close and open sessions in agent worktrees` versus `Disabled` / `the worktree tools are not registered`; preview line `Preview · <category> · <the focused row's effect>`; footer `←/→ or Tab panes · ↑/↓ move · Enter apply · Esc close`. Esc closes and writes nothing.
S3. Scope, answered by the user: "Solo los 3 toggles" — agentes sidebar, moshi notifications, worktree tools. The panel carries no fourth category and no worktree listing (that is `/herdr-gentle:warp`, S11).
S4. `/herdr-gentle:warp` is its own command (superseded from the earlier "argument path of customize" decision by L7): no argument opens a selector of the project's checkouts, an explicit `<name>` keeps today's behaviour byte for byte (worktree-tools S23/S24). Session control (`waitForIdle`, `switchSession`, `reload`) exists only on a command context, which is why this is a command and never a tool.
S5. Apply policy, answered by the user: "Caliente si se puede, reload si hace falta", reinforced by L7 ("lo de applicar en cliente y /reload cuando se requiere esta bien, pero recuerda que disable/enable de moshi modifica el setiings de pi, por eso el reload creo se necestia, y lo de worktree saca tools, asi que esta bien pero revisa bien si requiere alguna /reload"). Every change writes its state file first; then, only when the change cannot take effect without rebuilding the extension runtime, the command calls `ctx.reload()` itself. No surface may ever ask the user to run `/reload`: the notification says what changed and, only when a reload ran, that it reloaded. The per-switch verdict is fixed in S6 from the code's own gating, verified against the source, never assumed.
S6. Architecture, verified against the source. Placement: `extensions/gentle-worktree-tools.ts` registers `/herdr-gentle:customize`, because it already owns `executeWorktreeWarp` (`:3175`), the worktree mode gate and `libRequire` (`:30-36`); the panel view lives inline in that file, because a static import of a new sibling module would break the twelve test loaders that copy the extension to a temp `.mjs` with only package import lines stubbed. The sidebar and moshi actions stay exactly where they are — inline in `extensions/gentle-herdr-state.ts` (`sidebarEnable :1755`, `sidebarDisable :1825`, `writeMoshiFlag :1177`, `setMoshiExclusion :1261`, `moshiEnabled :2099`): none of the code that survived the adversarial rounds is extracted or rewritten. Reachability: one in-process provider slot, `globalThis[Symbol.for("herdr-gentle.customize.v1")]`, documented in `DESIGN.md` as the single cross-extension contract; the state extension writes `{sidebar:{read,apply}, moshi:{read,apply}}` at load and the worktree extension reads it when the panel opens. `Symbol.for` yields the same symbol in both modules without a shared import, so the key literal is the contract and a test asserts both files carry the identical literal. Provider contract: `read()` returns the active value id; `apply(value, ctx)` returns `{changed, needsReload, text}`. Fail closed: a missing or malformed provider renders that category as unavailable, `Enter` writes nothing.
   Reload matrix, from each switch's own gating:
   | Switch | What it writes | Hot effect | Reload |
   | --- | --- | --- | --- |
   | Agentes sidebar (Gentle/Native) | sidebar mode file, the Pi settings exclusion for the native `herdr-agent-state.ts`, and the managed Herdr sidebar rows through `bin/configure.js --apply\|--uninstall --reload` | the Herdr rows are re-applied by `configure` itself (Herdr-side reload) | ALWAYS: the Pi settings exclusion and the native sidebar only take effect on the next Pi extension load, so a running session keeps the previous publisher |
   | Moshi notifications | `gentle-moshi.json` flag, Pi settings exclusion for the Moshi-managed hook | the flag is re-read per event (`moshiEnabled :2099`, mtime-cached), so our sender silences or activates immediately | ALWAYS when the exclusion entry actually changed: it only applies at the next Pi load, so a running session would keep the other publisher loaded too |
   | Worktree tools | `lib/worktree-mode.js` mode file | the per-call gate in every execute refuses immediately (`:201`, `:831`, `:1555`, `:2477`, `:3016`) | only when the runtime's registration must change: `enabled !== toolsRegistered`, i.e. enabling while the runtime loaded disabled, or disabling while the tools are registered |
   Ordering, mandatory: the panel closes first (`done()`), then the notification, then `await ctx.reload()` — the overlay is never on screen while Pi rebuilds the extension runtime.

S10. Package metadata and test harness move with the panel: `@earendil-works/pi-tui` becomes a declared peer dependency (the view measures and truncates with `visibleWidth`/`truncateToWidth` and reads keys with `matchesKey`, as gentle-shell declares it), but it is resolved through a LAZY `await import("@earendil-works/pi-tui")` inside the command handler, exposed as an injectable seam for tests, so no test loader needs a new stub and a host without that module degrades to the plain `ctx.ui.select` menu instead of failing.
S11. `/herdr-gentle:warp` (user request, verbatim): "Igual tambien agrega un nuevo que sea /herdr-gentle:warp, que parecido sea como un popu selector, donde sale los worktrees del proyecto y pueda mover la sesion a uno de ellos. (Destacando como el primero y aparte el activo/actual, aunque este no se puede seleccionar, estaria arriba como texto). ej: worktree 1 - actual / worktree 2 - path ... algo asi, no lo tomes literal, es solo idea de la separacion, mejora el diseno y que debe decir claro."
   Fixed design: the active checkout is TEXT, never an option — it travels in the selector's title, because the host `select` primitive has no non-selectable rows and `Esc`/undefined is the cancel path. Title: `Warp session · current: <name> <path>`. Options: every other live checkout of the project in listing order (the principal first when the session is not in it, then the registry rows), each rendered as `<name> — <path>`, which is the identifier `warp <name>` accepts. Only registered checkouts and the principal are offered; a name carried by more than one live checkout keeps failing closed (S24); the session's own checkout is never offered. Nothing to offer (only the active checkout exists): notify `warp: no other checkout to move the session to` and open no selector. `Esc` cancels silently and changes nothing. An explicit `/herdr-gentle:warp <name>` skips the selector and is the scripted path.
S12. Decision (parent): `/herdr-gentle:customize status` keeps the read-only reporting the three removed commands offered, as one terse line per switch (`customize status: sidebar=gentle moshi=off worktree=enabled`). Rationale: the panel answers "what is on" only for a human looking at a screen, the user's original complaint was about not seeing the state, and this gives the panel's readers a headless, pinned contract to test without a TUI. It writes nothing.
